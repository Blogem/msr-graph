## Why

The knowledge graph and the agent demo currently stand on a hand-curated seed A-Box (`ontology/example-flibe.ttl`): a fabricated FLiBe salt/measurement duplicate plus connective facts (`skos:closeMatch` salt↔concept, `msr:hasRole`/`msr:usedIn`, the `msrd:MSRE` reactor) that no real document produced. That violates Principle 3 of `docs/PROVENANCE_AND_TRUST_DESIGN.md` — *only real data, nothing fabricated for demonstration* — and it is the load-bearing crutch of the agent: grounding reaches a salt only through the seed-only `skos:closeMatch` edge. This change **removes the hand-curated seed entirely** and re-grounds the graph and demo in real data. It lands **first** in the trust sequence — *make the data real (this) → make it provenanced (`provenance-model`) → enforce it (`shacl-validation`, chunk 13)* — so provenance and the write-time gate later apply to an all-real graph instead of validating or exempting fabricated facts.

Verified feasibility (live clone of `openmsr/msr-archive`): the real OCR of **`ORNL-TM-2316`** contains the composed mention **`"LiF-BeF, (66-34 mole %)"`** (lines 225, 370, 1335), which the OCR-robust linker resolves — via the `msr:Mention → msr:linksTo` edge it already emits — to `msrd:salt-BeF2-LiF-34.0-66.0`, the exact salt the NIST loader mints the density measurement for (1.974 g/cm³ at 900 K). So the FLiBe density demo survives on real data, and there is already an honest edge connecting a document's name for the salt to the salt individual — the agent should ground through *that*, not through a fabricated `skos:closeMatch`.

## What Changes

- **Delete `ontology/example-flibe.ttl` entirely** — the whole A-Box. `make load-seed` then loads only the TBox (`ontology/msr.ttl`) and SKOS terminology (`ontology/vocab.ttl`), which are real infrastructure the NER ruler seeds from (confirmed independent of the A-Box). **BREAKING** for anything assuming the seed A-Box is loaded.
- **Rework agent grounding to drop `skos:closeMatch` entirely** — in the `sparql_query` tool description (`internal/agent/sparql.go`) and the agent's grounding guidance: ground a **salt** via `Mention.surfaceForm → msr:linksTo → msr:MoltenSalt → PropertyMeasurement` (the honest edge the linker already emits), and ground a **property** by matching the query term against the `rdfs:label` of a `msr:PhysicalProperty` term directly. `skos:closeMatch` is **not used anywhere** in grounding — the salt↔concept *and* property-term↔concept forms were both the same SKOS abuse (range is `skos:Concept`; neither a salt individual nor a `msr:PhysicalProperty` is one). The matched Mention (with `msr:inDocument` + provenance) is the traceable grounding evidence.
- **Drop all `skos:closeMatch` (both `msr.ttl` and `vocab.ttl`) and the orphaned role/reactor layer from `msr.ttl`** — with grounding label/mention-based, every `skos:closeMatch` becomes unused and is removed: the forward links in `msr.ttl` (OWL-term→SKOS-concept) *and* the reverse links in `vocab.ttl` (SKOS-concept→OWL-term). They are the same abusive alignment asserted in opposite directions (the targets `msr:density`/`msr:MoltenSalt`/roles are not `skos:Concept`s), and several `vocab.ttl` links would otherwise dangle at the role/reactor terms removed below. The role/reactor TBox layer (`msr:SaltRole`/`FuelSalt`/`CoolantSalt`/`FlushSalt`/`hasRole`, `msr:MoltenSaltReactor`/`usedIn`) was populated only by the deleted seed; nothing writes it until chunk-7 relation extraction derives those facts from real text, so per the "defer capabilities without a real source" principle it is removed now and returns in chunk-7. Property terms keep their `rdfs:label`; the vocab keeps its **concepts** (`prefLabel`/`altLabel` seed NER) — only their `closeMatch` triples go; the mention/measurement/substance layers stay.
- **No special demo path** — grounding stays fully data-driven (dynamic vocab + salt catalog; generic SPARQL). Any illustrative example left in the tool descriptions is neutral, not a FLiBe-specific code path; it is acceptable that some queries won't ground perfectly — real data matters more than a demo hinging on special paths.
- **No linker change** — the composed-mention `msr:linksTo salt` edge already exists (chunk 6.1); this change consumes it. Vocab concepts remain for NER seeding and optional query-term synonym expansion, but are out of the grounding path.
- **Demo substance preserved** — the canonical density question and its 1.974 g/cm³ answer stay, grounded through the real `ORNL-TM-2316` mention. The salt is identified by its composition (which both NIST and the document carry); the vocab labels (including "FLiBe") are already in the agent's schema prompt, so how the user names the salt is immaterial to grounding. The demo's *precondition* changes: the graph must be built by the full real pipeline (`load-nist` + `ingest` + `link`), not a static seed.
- **Roles / reactor deferred** — `msrd:MSRE`, `msr:hasRole`, `msr:usedIn` are removed with the seed. `ORNL-TM-2316:371` does state the 66-34 melt "has been used in the MSRE as the coolant and as [flush]", so these are real, extractable facts — but their extraction is unbuilt chunk-7 relation work; the demo does not depend on them and they are not resurrected by hand.
- **Rework seed-dependent tests, specs, docs** — the Go integration tests that assert seed-only edges, the `analysis-agent`/`seed-graph-loading` specs, and the bootstrap docs that name `example-flibe.ttl`.

## Impact

- **Sequencing**: lands **first** — before `provenance-model`, which lands before `shacl-validation` (chunk 13). Order: *make the data real (this) → make it provenanced (`provenance-model`) → enforce it (shacl)*. This change has no functional dependency on `provenance-model`: grounding needs only the salt + measurement (loader) and the `mention → linksTo → salt` edge (linker) — none of which is provenance work.
- **Depends on**: the OCR-robust linker (`ocr-robust-salt-linking`, done).
- **Interim provenance gap (expected)**: after this change, measurements still carry `prov:wasDerivedFrom msrd:nist-srd27`, but that `Dataset` node (+DOI) is not defined until `provenance-model` — a harmless dangling IRI (RDF has no referential integrity; grounding never reads it). `provenance-model` completes the source nodes and the generation `Activity` trail. (A measurement↔document `msr:citedIn` edge is deferred to chunk-7 citation extraction — NIST SRD-27 has no per-row citation, so no writer can assert one truthfully yet; the demo's document trace comes from the grounding mention's `msr:inDocument`.)
- **Blocks**: `provenance-model` and `shacl-validation` (chunk 13) — removes the last fabricated data (the seed) so provenance and the write-time gate apply to an all-real graph.
- **Operational**: building the demo graph now requires `make up && make load-nist && make ingest && make link` (link's disambiguation may need `DEEPSEEK_API_KEY`); `make demo-density` depends on that full build. The guarded `MSR_LINK_INTEGRATION=1` test (`extraction/tests/test_link_integration.py`) — which already asserts a composed mention `msr:linksTo msrd:salt-BeF2-LiF-34.0-66.0` — becomes the authoritative end-to-end check that the grounding edge is real.
- **Docs/tests touched**: `internal/graph/seed_integration_test.go`, `internal/graph/nist_loader_integration_test.go`, `internal/agent/acceptance_test.go`, `cmd/server/chat_sse_test.go`, the `analysis-agent`/`seed-graph-loading`/`document-graph`/`salt-canonicalization` specs, and the `example-flibe.ttl` / `skos:closeMatch` references across `README.md`, `docs/ARCHITECTURE.md`, `docs/ONTOLOGY.md`, `docs/IMPLEMENTATION_PLAN.md`, `docs/DATA_SCOPE.md`, `docs/VOCABULARY.md` (friendly names come from vocab `prefLabel`/`altLabel`, not `closeMatch`; DIAMOND alignment stays via `rdfs:seeAlso`).
